# ShipAssistant — Operations Runbook

> **Audience:** Thesis committee members, external evaluators, and developers
> running the system for the first time.
> **Convention:** All commands are executed from the **project root directory**
> unless stated otherwise. All paths are relative to the project root.
> Angle-bracketed tokens (`<...>`) are placeholders — replace them with actual values.

---

## Prerequisites

| Requirement | Version | Notes |
|---|---|---|
| Python | 3.10 or 3.11 | 3.12 not yet tested with all transitive deps |
| pip | ≥ 23 | Bundled with CPython 3.10+ |
| Git | any | For cloning |
| RAM | ≥ 2 GB free | ONNX INT8 model loads ~733 MB RSS |
| CPU | x86-64 with AVX2 | Required by ONNX Runtime CPU provider |
| Microphone | any USB/analog | Required for `--mode realtime` only |
| GPU (CUDA) | optional | CPU inference runs out of the box |

## Step 1 — Clone the Repository

```bash
git clone <repository-url> ShipAssist
cd ShipAssist
```

## Step 2 — Create a Virtual Environment

```bash
python -m venv .venv
```

Activate:

```bash
# Windows — PowerShell
.venv\Scripts\Activate.ps1

# Windows — cmd
.venv\Scripts\activate.bat

# Linux / macOS
source .venv/bin/activate
```

Confirm the correct interpreter is active:

```bash
python --version      # must show 3.10.x or 3.11.x
which python          # Linux/macOS: should resolve inside .venv/
```

## Step 3 — Install Dependencies

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

If `requirements.txt` is absent, install the core stack manually:

```bash
pip install fastapi uvicorn pydantic pydantic-settings pyyaml \
            numpy soundfile onnxruntime torch transformers peft \
            sounddevice psutil librosa
```

> **Note on `onnxruntime` vs `onnxruntime-gpu`:** install only one. The CPU
> variant (`onnxruntime`) is the default and is sufficient for all benchmarks.

## Step 4 — Create Required Directory Structure

The config validator and logger expect these directories to exist before startup.
Run once after cloning:

```bash
mkdir -p artifacts/models/onnx_model
mkdir -p artifacts/models/best_model
mkdir -p artifacts/data
mkdir -p artifacts/benchmarks
mkdir -p logs
```

Expected layout:

```
artifacts/
├── models/
│   ├── onnx_model/       ← ONNX bundle (onnx_config.json + model_int8.onnx)
│   └── best_model/       ← PyTorch LoRA checkpoint (for training / torch backend)
├── data/                 ← dataset.csv and processed audio
└── benchmarks/           ← defense_metrics.json written here by demo_defense.py
logs/                     ← rotating JSON event log
```

## Step 5 — Place Model Artifacts

| File | Location | How to obtain |
|---|---|---|
| `model_int8.onnx` | `artifacts/models/onnx_model/` | Run the export script (Step 11) or copy a pre-built bundle |
| `onnx_config.json` | `artifacts/models/onnx_model/` | Generated by the export script alongside the `.onnx` file |
| `temperature.json` | `artifacts/models/onnx_model/` | Generated by calibration step in training (optional but recommended) |
| PyTorch checkpoint | `artifacts/models/best_model/` | Output of LoRA fine-tuning (Step 10) |

The path `artifacts/models/onnx_model` is the default value of `paths.onnx_model`
in `configs/base.yaml`. To use a different location, update that key — do not
hardcode paths anywhere else.

## Step 9 — Run Real-Time Recognition

Requires a connected microphone. The system listens continuously on a 1 s
sliding window (0.5 s stride) and prints every detection above the per-label
confidence threshold.

```bash
# ONNX INT8 backend — recommended for production
python src/inference.py --mode onnx

# PyTorch FP32 backend — for development and accuracy comparison
python src/inference.py --mode torch
```

Press `Ctrl+C` to stop cleanly.

## Step 10 — Configuration Reference

All tuneable parameters live in `configs/`. Edit YAML; do not touch source code.

| File | Controls |
|---|---|
| `configs/base.yaml` | Artifact paths, logging rotation size, API host/port |
| `configs/model.yaml` | Model name, engine type (`onnx`/`torch`), INT8 flag, per-label thresholds, benchmark sample count |
| `configs/inference.yaml` | Sample rate, window size, stride, VAD energy threshold |
| `configs/routing.yaml` | `SmartRouter` confidence floors, cosine alignment params, outlier-gate thresholds |
| `configs/hybrid/model.yaml` | Hybrid centroid model path and embedding dimension |
| `configs/hybrid/thresholds.yaml` | Per-class cosine similarity thresholds for the outlier gate |

Override any key for a single run with an environment variable:

```bash
# Switch backend without editing YAML
SHIP_MODEL__TYPE=torch python src/inference.py

# Change API port
SHIP_API__PORT=9000 python src/api.py

# Lower confidence threshold for debugging
SHIP_MODEL__DEFAULT_CONFIDENCE=0.5 python src/api.py
```

## Training Pipeline (from scratch)

Follow these steps in order to reproduce the fine-tuned model from raw audio.

### Step 11a — Prepare the Dataset

```bash
# Download and assemble Mozilla Common Voice (Russian subset)
python scripts/data/main_mozilla_make_dataset.py

# Convert all audio to WAV, 16 kHz, mono
python scripts/preprocessing/main_audio_to_wav.py

# Augment with maritime noise (engine drone, wind, intercom band-limiting)
# SNR range 0–20 dB; only training split is augmented
python scripts/preprocessing/main_aug_audio.py --maritime_noise true

# Build final dataset CSV with speaker-disjoint splits
python scripts/data/main_post_parsing.py
```

### Step 11b — Verify Split Integrity (Critical)

Run the split verifier before training. It asserts:
- `train ∩ val ∩ test = ∅` (no group overlap).
- No speaker appears in more than one split.
- No augmented copy of a training clip leaks into val or test.

```bash
python scripts/main_verify_splits.py \
    --csv artifacts/data/dataset.csv \
    --group_col audio_group

# Expected output on a clean split:
# [PASS] train ∩ val = ∅ (0 overlapping groups)
# [PASS] train ∩ test = ∅ (0 overlapping groups)
# [PASS] val ∩ test = ∅ (0 overlapping groups)
# [PASS] No speaker-level leakage detected
# Split verification PASSED.
```

If any `[FAIL]` lines appear, fix `scripts/data/main_post_parsing.py` before
proceeding. **Do not report test metrics from a leaking split.**

### Step 11c — LoRA Fine-Tuning

```bash
python src/train.py \
    --config configs/model.yaml \
    --output_dir artifacts/models/best_model \
    --use_maritime_aug true \
    --lora_r 32 \
    --lora_alpha 64 \
    --lora_target_modules q_proj,v_proj,out_proj \
    --epochs 50 \
    --batch_size 8 \
    --grad_accum_steps 4
```

> **Critical — LoRA target modules:** ensure the comma-separated list contains
> `q_proj`, `v_proj`, and `out_proj` as **separate strings**. A Python
> string-literal concatenation bug in earlier script versions collapsed
> `"v_proj" "out_proj"` into `"v_projout_proj"`, silently excluding `out_proj`
> from adaptation. The CLI argument form above is immune to this bug.

Monitor training:

```bash
tensorboard --logdir artifacts/models/best_model/runs
# or, if WandB is configured:
wandb login && python scripts/train/main_full_tune_lora.py --wandb true ...
```

### Step 11d — Export to ONNX INT8

```bash
python scripts/train/main_export_to_onnx.py \
    --model_dir artifacts/models/best_model \
    --output_dir artifacts/models/onnx_model \
    --quantize \
    --validate \
    --benchmark
```

The `--validate` flag asserts that INT8 ONNX accuracy delta vs PyTorch FP32
is ≤ 1 pp F1 on the validation set. If the assertion fails, the export script
exits with a non-zero code and a diagnostic message — **do not deploy an
unvalidated model.**

Expected validation output:

```
[PASS] ONNX FP32 accuracy delta vs PyTorch: 0.21 pp  (threshold: 1.00 pp)
[PASS] ONNX INT8 accuracy delta vs FP32:    0.38 pp  (threshold: 1.00 pp)
Model exported → artifacts/models/onnx_model/model_int8.onnx
Config exported → artifacts/models/onnx_model/onnx_config.json
```

### Step 11e — Calibrate Confidence Thresholds

After export, calibrate the router's confidence floor against the validation set
to achieve FPR ≤ 1 % on noise / silence audio:

```bash
python scripts/train/main_calibrate_temperature.py \
    --onnx_dir artifacts/models/onnx_model \
    --val_csv artifacts/data/dataset.csv \
    --noise_dir artifacts/data/maritime_noise \
    --target_fpr 0.01
```

The script outputs recommended per-label thresholds and writes them to
`configs/routing.yaml` automatically. Review and commit the change.

## Troubleshooting

**`ConfigError: ONNX model directory not found`**

The path in `configs/base.yaml` → `paths.onnx_model` does not exist or does
not contain `onnx_config.json`. Either run the export script (Step 11d) or
update the YAML to point to an existing bundle:

```yaml
# configs/base.yaml
paths:
  onnx_model: "artifacts/models/onnx_model"
```

---

**`ModuleNotFoundError: No module named 'onnxruntime'`**

```bash
pip install onnxruntime
```

---

**`ModuleNotFoundError: No module named 'pydantic_settings'`**

```bash
pip install pydantic-settings
```

---

**`sounddevice.PortAudioError` on microphone open**

- Confirm no other application is holding the microphone.
- On Linux, install PortAudio: `sudo apt install portaudio19-dev`.
- List available devices: `python -c "import sounddevice as sd; print(sd.query_devices())"`.
- Override the device index: `SHIP_AUDIO__DEVICE_INDEX=1 python src/inference.py`.

---

**High latency in real-time mode (> 200 ms)**

Confirm INT8 is active:

```bash
python -c "
from core.config import load_config
s = load_config('configs/base.yaml', 'configs/model.yaml', 'configs/inference.yaml')
print('Engine:', s.model.type, '| INT8:', s.model.onnx.use_int8)
"
# Expected: Engine: onnx | INT8: True
```

If `INT8: False`, set `onnx.use_int8: true` in `configs/model.yaml`.

---

**Port 8000 already in use**

```bash
SHIP_API__PORT=9000 python src/api.py
```
